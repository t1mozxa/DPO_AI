## 2. Постановка задачи и контекст

Опишите:

1. **Предметная область**
Задача относится к области регрессии — предсказания непрерывной числовой величины (цены автомобиля в INR). Потенциальные пользователи сервиса:
Покупатели подержанных авто — чтобы оценить, справедливая ли цена;
Продавцы и автодилеры — для корректного ценообразования;
Страховые и финансовые компании — для оценки стоимости залога.

Сценарий использования: клиент отправляет запрос с характеристиками автомобиля (марка, год, пробег, тип топлива и т.д.) и получает предсказанную цену.

2. **Формулировку задачи в терминах ML/ИИ:**
Входные данные: 19 признаков, среди которых числовые (год, пробег, мощность, объём двигателя) и категориальные (марка, модель, тип топлива, цвет, город).
Целевая переменная: Price — цена автомобиля (предсказывается её логарифм log1p(Price) для стабилизации дисперсии).
Ограничения:
Скорость ответа API — не более 1 секунды;
Интерпретируемость — возможность показать важность признаков;
Точность — R² на тестовой выборке не ниже 0.6.

3. **Целевые метрики качества:**

| Метрика | Значение | Почему выбрана |
|---------|----------|----------------|
| R² (log) | 0.6433 | Показывает, какую долю дисперсии объясняет модель |
| RMSE (log) | 0.6915 | Штрафует за большие ошибки в логарифмической шкале |
| MAE (log) | 0.5317 | Средняя абсолютная ошибка, устойчива к выбросам |
| MAPE (%) | 69.35 | Процентная ошибка в исходной шкале — интуитивно понятна бизнесу |

## 3. Данные

Опишите, какие данные использует проект:

1. **Источник данных:**
   Использован открытый датасет used_car_price_prediction_1M.csv (https://www.kaggle.com/datasets/sharmajicoder/used-car-price-prediction-dataset). Для ускорения экспериментов формировалась стратифицированная выборка объёмом 10 000 строк (сохраняется в data).
2. **Структура данных:**
Датасет содержит 20 колонок:
Числовые признаки (12): Year, Mileage_kmpl, Engine_CC, Horsepower, Kms_Driven, Insurance_Valid, Service_History, Accidents, Tax_Paid, Number_of_Doors, Seats, Registration_Age.
Категориальные признаки (7): Brand, Model, Fuel_Type, Transmission, Owner_Type, Color, City.
Целевая переменная: Price.

3. **Предобработка и EDA:**
Основные шаги реализованы в src/data.py:
1. Очистка от выбросов (clean_data):
Удаление записей с отрицательной ценой;
Фильтрация годов выпуска (1990–2025);
Ограничение пробега (0–500 000 км), мощности (0–2000 л.с.), объёма двигателя (0–10 000 см³), расхода (0–100 км/л);
Оставление только топ-50 самых популярных моделей.
2. Нормализация текстовых значений:
Удаление лишних пробелов (.str.strip());
Приведение к Title Case;
Исправление опечаток в Fuel_Type (Electrik → Electric, Hybridd → Hybrid и т.д.).
3. Заполнение пропусков (handle_missing_values):
Числовые признаки — медианой по группе Brand;
Категориальные — модой по группе Brand;
Оставшиеся NaN — нулями / 'Unknown'.
4. Логарифмирование целевой переменной: y = log1p(Price).
5. Разделение на train/test (75/25, random_state=42): 5565 строк на обучение, 1855 на тест.
6. Построение пайплайна предобработки (ColumnTransformer):
StandardScaler для числовых признаков;
OneHotEncoder(handle_unknown='ignore') для категориальных.

Ключевые наблюдения из EDA:
Распределение цен сильно асимметрично (медиана ~5–7 lakh INR, максимум >100 lakh);
Пробег (Kms_Driven) — наиболее коррелирующий с ценой признак;
В исходных данных встречались дубликаты категорий из-за опечаток и пробелов.

## 4. Модели и подходы

Опишите, какие модели вы пробовали и как развивался ваш подход:

1. **baseline модели:**
В качестве стартовой точки были выбраны классические алгоритмы из sklearn.ensemble:
GradientBoostingRegressor (300 деревьев, max_depth=4, loss='huber' для устойчивости к выбросам);
RandomForestRegressor (300 деревьев, max_depth=20).

2. **Улучшенные модели и эксперименты:**
Для сравнения были добавлены современные реализации градиентного бустинга:
XGBoost (XGBRegressor) — с регуляризацией reg_alpha=0.1, reg_lambda=1.0, subsample=0.8;
LightGBM (LGBMRegressor) — быстрый бустинг от Microsoft с аналогичными гиперпараметрами.
Все модели обучались с одинаковыми базовыми настройками (n_estimators=300, learning_rate=0.1, max_depth=4), чтобы сравнение было честным.

Сравнение моделей и анализ важности признаков проведены в ноутбуке notebooks/02_models_comparison.ipynb. Разведочный анализ данных и визуализация распределений признаков — в ноутбуке notebooks/eda.ipynb. В ноутбуке с экспериментами показано обучение 4 моделей (Gradient Boosting, Random Forest, XGBoost, LightGBM), их сравнение по метрикам R², RMSE, MAE, MAPE, а также 5-fold кросс-валидация. Финальный выбор пал на Random Forest как модель с наилучшим балансом качества и устойчивости.

## 5. Экспериментальный протокол и результаты

Здесь важно показать, что выбор финальной модели был осмысленным.

1. **Экспериментальный протокол:**
Разделение: 75% train / 25% test (стратифицированное, random_state=42);
Кросс-валидация: 5-fold CV по тренировочной выборке, метрика — R²;
Финальная оценка: на hold-out тестовой выборке (1855 объектов), не участвовавшей в обучении и подборе гиперпараметров.

2. **Сравнение моделей по метрикам:**

| Модель | RMSE (log) | MAE (log) | R² (log) | MAPE (%) | CV R² (5-fold) | Комментарий |
|--------|------------|-----------|----------|----------|----------------|-------------|
| Gradient Boosting | 0.6993 | 0.5266 | 0.6352 | 73.10 | 0.6315 ± 0.0129 | Стабильный baseline |
| Random Forest | 0.6915 | 0.5317 | 0.6433 | 69.35 | 0.6400 ± 0.0168 | Финальная модель |
| XGBoost | 0.6956 | 0.5354 | 0.6391 | 69.79 | 0.6331 ± 0.0133 | Быстрее GBM, но чуть хуже |
| LightGBM | 0.6942 | 0.5340 | 0.6405 | 69.49 | 0.6295 ± 0.0137 | Очень быстрый, хорошее качество |

3. **Выбор финальной модели:**
Random Forest выбран как финальный по следующим причинам:
Наивысший R² на тесте (0.6433) и на кросс-валидации (0.6400);
Наименьший MAPE (69.35%) — предсказания ближе к реальности в абсолютных рублях;
Устойчив к выбросам и не требует тщательной настройки гиперпараметров;

## 6. Архитектура решения и сервис

Опишите, как из модели получился работающий сервис:

1. **Архитектура пайплайна:**
[CSV данные] 
    ↓
[src/data.py] → load_and_preprocess() → очистка, заполнение пропусков
    ↓
[src/train.py] → обучение 4 моделей, выбор лучшей по R²
    ↓
[artifacts/] → car_price_model.pkl, preprocessor.pkl, metrics.json
    ↓
[src/service.py] → FastAPI-сервис, загружает артефакты при старте
    ↓
[Swagger UI] → http://127.0.0.1:8000/docs

2. **API и endpoints:**

| Endpoint | Метод | Описание |
|----------|-------|----------|
| `/` | GET | Корневой, список доступных endpoints |
| `/health` | GET | Проверка состояния сервиса и загруженности модели |
| `/predict` | POST | Предсказание цены для одного автомобиля |
| `/predict_batch` | POST | Пакетное предсказание для списка автомобилей |
| `/metrics` | GET | Метрики качества обученной модели |
| `/features` | GET | Важность признаков (feature importance) |

/predict принимает JSON с 20 полями (Pydantic-модель CarInput) и возвращает PredictionResponse с предсказанной ценой и её логарифмическим значением.

3. **Технологический стек:**
Python 3.11+
ML: scikit-learn, xgboost, lightgbm, pandas, numpy
Сервис: FastAPI, uvicorn, pydantic
Сериализация: joblib
Тесты: pytest

Команды для запуска:

# Обучение модели
python -m src.train

# Запуск API
uvicorn src.service:app --reload --host 0.0.0.0 --port 8000

# Запуск тестов
python -m pytest tests/ -v

## 8. Ограничения и дальнейшая работа

Качество: R² ≈ 0.64 — модель объясняет около 64% дисперсии цен. Оставшиеся 36% — это шум, редкие премиальные авто и неучтённые факторы (состояние салона, история ДТП в деталях).
MAPE ≈ 69% — высокая процентная ошибка связана с тем, что дешёвые авто (цена ~1 lakh) модель предсказывает с большой относительной ошибкой.
Данные: используется только выборка 10 000 из 1 млн строк — на полном датасете качество может вырасти.
Категории: One-Hot Encoding для Model (50 категорий) сильно расширяет пространство признаков.
 
Улучшить можно признаки, точнее попробовать добавить взаимодействия (Year * Mileage, Engine_CC / Horsepower), также добавить Docker-контейнер, кэширование предсказаний, логирование запросов в PostgreSQL.
